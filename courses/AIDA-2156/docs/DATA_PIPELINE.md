# Data splits, transformations and pipeline

[中文](DATA_PIPELINECN.md) · [Data sources](DATA_SOURCES.md) · [Documentation index](README.md)

> **V4 is the retained course research checkpoint, not a flood-warning or response system.** Final historical test and release decision: [Model experiments](MODEL_EXPERIMENTS.md).

## 1. From source observations to a learning row

**Archived WSC flow/stage + ECCC hourly rain + surveyed datum → verified PostgreSQL staging → branch travel-time and five-minute arrival volumes → arrival audit → 12 features and one terminal label → chronological partitions → six-block MLP → retrospective evaluation.**

1. **Source and storage.** Freeze source manifests, preserve UTC observation times, quality and receipt metadata, deduplicate station/parameter/time records, and stage checked river/weather data in PostgreSQL. The fitted V4 read the local database `red_deer_river`, versioned schema `rdr_unit_0f36881e431d0966`. It did not read the older recursive ETL CSV/SQLite dataset as its feature matrix. The recorded query bounds were 2025-05-03 00:00 UTC inclusive to 2026-11-12 00:00 UTC exclusive; they are not a promise of complete observed coverage.
2. **Match the different source clocks.** Control flow, Little Red Deer and Medicine observations do not arrive downstream simultaneously. For Dickson and Little Red Deer, assign each measured five-minute interval once as a parcel of `Q × 300 s`. Invert the stored historical timing hint within a half-bin (2.5 min); if it is absent, use the nearest valid lag hint within three source-clock hours, otherwise use nominal 10h30 for Dickson or 9h for Little. Bound usable lag hints to 2–30 h and 1–36 h, respectively. Coincident parcels in the same branch and arrival bin add their volumes; divide by 300 s to recover an equivalent flow. This accounts for successive source intervals arriving together without counting the same measured short-route interval twice. The bounds and fallback are experimental assumptions, not validated speeds.
3. **Spread Medicine arrivals.** Estimate a center lag from a trailing upstream rise using a preceding 6 h observation (up to 6h15 if needed), with at least 75% history coverage and no gap over 30 min in that history. Use a 50h15 default, decreasing toward 30 h only when the configured absolute and proportional rises support it. Spread each source parcel over 73 five-minute arrival bins (`k = −36…36`, weight `(37−|k|)/1369`), with weights summing to one. Sum overlapping contributions in each bin and divide by 300 s for the equivalent discharge. This approximates travel-time dispersion while conserving parcel volume across the full kernel; the kernel is not independently validated hydrodynamics.
4. **Attach rain to each branch's source time.** Use the airport hour immediately before the hour containing the contributing upstream observation (UTC floor to hour minus one hour). Compute inclusive trailing totals of 1, 6 and 24 hourly amounts. Unknown rain contributes zero to the totals, with flags/counts retained in the audit. Aggregate rain within an arrival branch by contributing volume; for zero-volume measured Dickson/Little parcels use the arithmetic mean of their source weather. Missing Dickson instead uses its intended source time. Keep all three branch groups separate; window totals overlap and are not independent rainfall amounts.
5. **Join and distinguish missingness.** Start with observed terminal discharge timestamps, then left join the branch arrivals and exact terminal depth context. If Dickson has no routed parcel, its output is explicitly 0 m³/s with zero parcels and a missing/imputed flag. This project convention keeps gaps on a regulated branch usable; it does not prove the dam released zero. Do not assign synthetic zero to missing Little Red Deer or Medicine. The audit retains incomplete rows and possible source-gap flags; a possible-gap flag is not itself the training filter when numeric arrivals exist. The training view includes three numeric branch flows and a nonnegative eligible endpoint proxy. It returned 146,319 rows; the numerical training preflight did not reject any additional row.
6. **Build the terminal label.** For 05CC002, add the published 847.992 m gauge adjustment to reported stage, then subtract the nearby surveyed bed proxy of 849.5955450123237 m in CGVD2013_e2010. Thus `label_endpoint_depth_proxy_m = reported stage − 1.6035450123237 m`. The 2017 surveyed point MD201709230317 (R38) was about 96 m from the gauge, which was relocated in 2019. Invalid or below-zero proxy values are not usable labels. A fixed datum shift leaves timing unchanged and does not establish real depth at the gauge or at the intermediate sections.

Key implementation: [short-volume matching](../analysis/eda_tools/routing_short_volume.sql), [routing and audit views](../analysis/eda_tools/routing_views.sql), [datum and import controls](../analysis/eda_tools/import_unit_postgres.py), and [V4 split/training implementation](../analysis/rdr_ml/train_routing_depth.py).

## 2. The V4 feature contract

The ordered input is Q from Dickson, Little Red Deer and Medicine, then the 1/6/24 h rain totals for Dickson, Little Red Deer and Medicine, in that order (12 variable values). Per-block distance and chainage supply fixed geometry context. The cascade estimates P01 through P05 and 05CC002, passes its prior block's latent state forward along the **spatial** chain, and is trained on endpoint proxy depth only. It is not a temporal recurrent model. Terminal discharge is useful for identifying evaluation events and constructing the historical arrival clock. Neither terminal discharge nor measured endpoint depth is directly fed to the twelve neural features; the upstream timing step still used terminal history indirectly.

## 3. Original V4 chronological partitions

The two protocols held out the **oldest** timestamps, with the newest period for gradient fitting. This retained the larger 2026 peaks (172 and 284 m³/s) for training while reserving the complete 2025 flood cases (150 and 116 m³/s) for historical evaluation. This design was intended to check transfer to earlier events, **not** to emulate forecasts trained before those events. Define events by terminal Q ≥100 m³/s, merge exceedance gaps up to 72 h, and pad each event by 72 h. Select event-safe split cuts; exclude seven days on either side of each boundary to avoid close-source overlap. The reviewed input lookback was 78h15, shorter than one side of the embargo; this does not undo the terminal-derived historical lag alignment.

The 60/20/20 boundaries were 2025-08-18 13:25 and 2025-12-11 09:25 UTC. The comparison **80/20** used the identical 27,256 test row IDs and 115,159 retained rows in the outer training pool (one cut; 3,904 excluded). For epoch selection only, its training pool was further split by time with the same embargo logic: 90,309 fitting, 21,020 validation and 3,830 excluded in this inner split. After selection, it was freshly refit on all 115,159 outer training rows. These partition counts differ intentionally from a previous 95,053-row unit-value study and its own snapshot view counts.

Both used training-only `log1p` feature means/stds (std floor 0.001, standardized clipping to ±8), training-only label scaling and endpoint MSE. Shuffle fitting minibatches (seed 42) only **after** chronological assignment; absolute timestamps remain audit keys and are not features. The matched training used batches of 512, Adam with learning rate 0.001, at most 50 selection epochs and patience 15; the validation check selected epoch 1, and the selection loops stopped after epoch 16. Validation selected checkpoints, not historical test error.

Evidence: `data/processed/segment_six_mlp_matched_early_stop_20261118T0108Z/v4_retrain/` contains `preflight.json`, `training_report.json`, `prepared_inputs.npz` and `predictions_60_20_20.npz`. The nominal 60/20/20 name refers to row-count proportions before event/overlap protection. Later replays of these 27,256 records are not independent blind tests.

## 4. Limits on interpretation

Dickson and Little lag hints were originally built with downstream event and stage-of-wave context from the historical record, even though the attached upstream observations precede their arrival timestamps. Ordinary split isolation prevents using test error for checkpoint optimization, but cannot make this precomputed alignment prospective. The model reconstructs a point target on a known historical arrival grid; it was not evaluated as a fixed-issue-time forecast or a direct future-stage-change predictor. The later past-only fixed-lag and retraining experiments are separate protocols in [Data improvement](DATA_IMPROVEMENT.md); their inputs, coverage and target type are not interchangeable with original V4.

## Relation to the current package

The historical split, routing, and outcomes above do not apply directly to the cloud adapter. The service uses the immutable weights but a separate as-of route and database; it never uses observed terminal flow as an input and never backfills missing live inputs from historical experiment artifacts.
